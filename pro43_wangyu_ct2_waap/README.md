# 网御星云 CT2-WAAP — 环境检查挑战思路档案

> 复现对象：`spider research/其他/pro51  网御星云 WAF` · 技术分类：`waf` `env` · 状态：📄 仅思路（不提供直接复现）

## 产品与目标

- 防护产品：网御星云 CT2-WAAP（响应头 `Server: CT2-WAAP`）
- 触发形态：412 `Environment Checking` 挑战页；失败后进入 NWAF 拦截页
- 分析目标：某市级政府门户（不记录真实域名、IP、UA、Cookie 与投放脚本哈希）
- 研究范围：防护架构、挑战阶段、服务端信任边界与防御启示

## 技术要点

- 两段式：先做浏览器环境检查，再由服务端登记设备身份并签发短时凭证
- 凭证按环境判定/查询等用途拆分；时间窗短，页面侧会周期性重签
- 客户端采集 WebDriver、headless、WebGL/Canvas/Audio、UA、语言、插件等信号
- 服务端并非只验客户端分数：设备身份、时间窗、UA 一致性、脚本版本都会参与
- TLS/JA3 不是主要门槛；真正的状态在“已登记设备 + 新鲜凭证”

## 思路摘要

- 入口：412 挑战页 → 加载挑战脚本 → 环境采集 → 写入多类 Cookie → 刷新页面
- 观察：设备身份由服务端在首次挑战中登记；纯离线伪造即使格式正确也会被拒
- 分析方法：Cookie setter Hook 观察写入顺序；静态提取关键函数；必要时用 CDP/路由拦截观察加密调用（仅概念，不提供代码）
- 服务端语义：设备登记表 + 短 TTL + 凭证类型隔离 + UA 一致性；客户端风险分不是唯一判据
- 关键难点：设备身份的“登记制”而非“校验和制”，使无状态纯算复现不成立

## 不复现声明

- 本档案不包含可执行客户端、Token 铸造代码、Cookie/密钥/UA/域名/脚本哈希，也不提供绕过步骤
- 仅用于授权安全研究、防护评估与教学；请遵守目标站点条款与适用法律
- 语义 WAF 仍会拦截注入/攻击特征；本档案不涉及此类能力

## 防御启示

- 不要把客户端风险分当作唯一信任依据；服务端应复算关键环境与设备一致性
- 设备登记 + 短时凭证 + 类型隔离能显著提高无状态伪造成本
- 同时评估隐私与可访问性：过度采集环境信号会带来合规与兼容性风险
