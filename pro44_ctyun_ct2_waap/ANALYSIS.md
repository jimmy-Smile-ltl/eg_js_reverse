# 电信云堤 CT2-WAAP 风险评分与信任边界

> 本文只讨论产品形态、挑战流程与防御启示，不提供可执行复现、Token 铸造代码、密钥、Cookie 值、真实域名/IP/UA 或脚本哈希。

## 1. 产品指纹

| 观察点 | 结论 |
|--------|------|
| 响应头 | `Server: CT2-WAAP` |
| 首次访问 | 412，页面为“加载中”型挑战页 |
| 挑战资源 | 动态配置脚本 + 大体量混淆 bundle |
| 拦截页 | 405 页面，含防护产品文案与事件编号 |
| 同族复用 | 部分同族站点共享同一 bundle，配置脚本按站点/轮次变化 |

## 2. 挑战流程（概念图）

```text
GET /
  → 412 挑战页
  → 加载动态配置脚本（站点/轮次相关）
  → 加载大 bundle（混淆 + 自校验）
  → 采集环境/行为信号，生成风险评分
  → 写入多类 Cookie（环境、设备、指标、查询）
  → reload
  → 服务端校验：环境风险、设备登记、UA、时间窗、脚本版本
  → 200 放行 / 405 拦截
```

关键观察：**挑战完成不等于放行**。如果环境风险分过高，服务端仍会在 reload 后返回 405；这与“只验签名”的 WAF 不同。

## 3. 检测能力分类

从 bundle 字符串表和行为对拍可以归纳出几类检测：

| 类别 | 典型信号 | 防御价值 |
|------|----------|----------|
| 自动化框架 | WebDriver、Selenium、Appium、Cypress、Playwright、Puppeteer 等痕迹 | 识别常见自动化栈 |
| 调试协议 | CDP 的 evaluate/attach/navigate 等特征 | 识别脚本化控制 |
| 无头特征 | headless 渲染、插件、字体、屏幕、UA-CH 异常 | 识别无头浏览器 |
| 图形/音频 | WebGL 软渲染、Canvas、Audio、字体一致性 | 提高设备指纹区分度 |
| 时序/行为 | 首屏时序、事件序列、控制台 hook | 识别异常交互节奏 |
| 客户端评分 | 上述信号的加权风险分 | 把复杂判断压缩为可传输信号 |

这些信号本身有误伤和隐私成本；是否采用、如何加权，需要结合业务风险评估。

## 4. 服务端信任边界

| 信号 | 客户端可控性 | 建议的服务端处理 |
|------|--------------|------------------|
| 环境风险分 | 高（可伪造） | 只作为辅助信号，服务端复算关键一致性 |
| 设备身份 | 中（需登记） | 校验登记表、生命周期与绑定关系 |
| UA/语言/屏幕 | 高（可伪造） | 与设备、凭证、时间窗交叉约束 |
| 凭证时间戳 | 低（受时间窗约束） | 校验新鲜度、一次性/短 TTL |
| 脚本版本/hash | 低（服务端下发） | 校验版本白名单与轮换状态 |

**最重要的教训：** 如果服务端直接信任客户端计算的风险分，攻击者只要能让客户端输出“低风险”，就能绕过整套检测。客户端评分必须与服务端可验证的信号（设备登记、时间窗、UA 一致性、脚本版本）组合使用。

## 5. 同族 bundle 的工程影响

- 同族站点共享 bundle 可以降低维护成本，但会把单点泄露/单点漏洞的影响扩大到多个站点。
- 动态配置脚本按站点/轮次变化，有助于差异化，但也增加配置一致性与回滚难度。
- 大 bundle + 自校验提高了分析成本，但不等于安全：客户端代码最终都在攻击者可控环境中执行。
- 防御方应关注**服务端可验证的状态**，而不是把更多逻辑塞进客户端。

## 6. 分析方法的合规边界

原始分析使用过动态调试、CDP 断点、路由拦截与对拍实验。本文只保留方法论结论：

- 先用行为对拍区分“客户端评分”与“服务端拒绝”；
- 再定位环境信号如何进入凭证；
- 最后验证服务端到底校验哪些字段。

**不提供**：Hook 代码、bundle 补丁、密钥、Cookie 值、设备号、脚本哈希与可执行客户端。

## 7. 防御启示

1. **服务端复算**：设备、时间、UA、脚本版本至少有两项能在服务端独立验证。
2. **风险分只作辅助**：不要把客户端评分当作唯一放行条件。
3. **短 TTL + 轮换**：凭证短时有效、脚本版本可轮换，降低重放与长期利用价值。
4. **同族隔离**：共享 bundle 要有版本隔离、灰度与快速回滚能力。
5. **隐私与误伤**：环境采集越深，合规成本和误伤概率越高；应做最小必要采集。
6. **分层防护**：人机挑战只是第一层，语义 WAF、速率限制、账号风控仍需独立生效。

## 8. 结论

电信云堤 CT2-WAAP 的挑战设计体现了“客户端采集 + 风险评分 + 服务端状态”的组合思路。其安全强度不取决于 bundle 有多难读，而取决于服务端是否真正复算并约束关键信号。对研究者，这是理解有状态 WAF 的案例；对 defenders，这是一份关于“不要信任客户端评分”的反面教材。
