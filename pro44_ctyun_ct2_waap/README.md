# 电信云堤 CT2-WAAP — 客户端风险评分与动态挑战思路档案

> 复现对象：`spider research/其他/pro52 电信云堤` · 技术分类：`waf` `env` · 状态：📄 仅思路（不提供直接复现）

## 产品与目标

- 防护产品：中国电信云堤（响应头 `Server: CT2-WAAP`，与 CT2-WAAP 同族）
- 触发形态：412 挑战页；挑战完成后仍可能因环境风险分进入 405 拦截页
- 分析目标：某市级政府门户（不记录真实域名、IP、UA、Cookie 值与脚本哈希）
- 研究范围：动态配置脚本、bundle 检测能力、客户端风险评分与服务端信任边界

## 技术要点

- 挑战由动态配置脚本 + 大体积混淆 bundle 组成；bundle 会做多层自校验
- 检测面覆盖 WebDriver/Selenium/Playwright/Puppeteer、CDP 特征、headless、WebGL/Canvas/Audio、UA-CH、首屏时序等
- 客户端把环境评分写入凭证；服务端据此决定放行或进入 405 拦截页
- 设备身份需要真实浏览器首次登记；回放还要求 UA 等请求特征逐字节一致
- 与网御星云 CT2-WAAP 同族：环境采集 + 设备状态 + 短时凭证的组合，而不是单一签名算法

## 思路摘要

- 入口：412 挑战页 → 动态配置脚本 → 大 bundle → 多轮 Cookie 写入 → reload
- 观察：同一 bundle 可在同族站点间复用；动态配置脚本按站点/轮次变化
- 分析方法：动态调试确认检测项；CDP 断点观察加密调用；对拍确认服务端边界（仅概念，不提供代码）
- 服务端语义：环境风险分、设备登记、UA 一致性、时间窗与脚本版本共同参与判定
- 重要教训：若服务端直接信任客户端风险分，安全强度会被“客户端可伪造”这一点上限约束

## 不复现声明

- 本档案不包含完整可执行客户端、端到端 Token 铸造/请求重放；关键实现仅以去密钥/去实例值的示意片段出现，不可直接运行
- 不含 Cookie/密钥/UA/域名/脚本哈希，也不提供绕过步骤
- 仅用于授权安全研究、防护评估与教学；请遵守目标站点条款与适用法律
- 语义 WAF 仍会拦截注入/攻击特征；本档案不涉及此类能力

## 防御启示

- 客户端风险分只能作为信号，服务端必须复算关键一致性（设备、UA、时间、脚本版本）
- 大 bundle + 多轮 Cookie 提高分析成本，但不能替代服务端有状态校验
- 动态配置与短时凭证有利于轮换，但要同时考虑可观测性、误伤与隐私合规
- 同族站点共享 bundle 会扩大单点泄露的影响面，应做版本隔离与灰度回滚
