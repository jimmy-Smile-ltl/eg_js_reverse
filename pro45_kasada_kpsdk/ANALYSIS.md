# Kasada / KPSDK 挑战架构与信任边界

> 本文只讨论产品形态、挑战流程与防御启示，不提供完整可执行客户端；关键实现仅以去密钥/去实例值的示意片段出现，不可直接运行。不含真实域名/IP/UA/Cookie/密钥/设备号/脚本哈希。

## 1. 产品指纹

| 观察点 | 结论 |
|--------|------|
| 响应头 | `x-kpsdk-*` 家族：挑战令牌、阶段标记、挑战参数与回执等产品级字段 |
| 首访形态 | 429 空挑战页（挑战型），或 200 正常页 + 后台传感器（传感器型） |
| 挑战资源 | 两段 UUID 形式路径下的 `ips.js`，以及 `mfc` / `tl` 两段式交互（路径实例值省略） |
| 完成信号 | `tl` 返回回执；主文档阶段标记由“挑战中”转为“已建立”，随后写入会话 |
| 会话命名 | 因实例而异；名称与值均省略 |
| 全局复用 | 多个实例共享同一挑战资源；脚本路径、版本号与哈希均省略 |
| 页面内标记 | 正常业务页也会出现 `KPSDK.configure(...)`；不能仅凭该字样判定为挑战页 |

## 2. 两种触发形态

| 形态 | 首访 | 客户端行为 | 服务端语义 |
|------|------|------------|------------|
| A. 挑战型 | 429 + 挑战阶段标记 | 加载挑战资源、计算 PoW/加密 bundle、提交回执、reload | 通过后发放会话；未通过继续 429 |
| B. 传感器型 | 200 + 传感器阶段标记 | 正常渲染，后台采集环境/行为信号并写入会话 | 画像直接放行，但仍有传感器与阶段标记 |

关键观察：**200 不等于没有 Kasada**。传感器型实例只是把“挑战”换成了后台信号采集；响应头、挑战资源与阶段标记仍然存在。排查时若只看状态码，会把 B 类误判为无防护。

## 3. 挑战状态机

```text
GET target
  ├─ 429 challenge
  │    → challenge script（两段式资源路径）
  │    → mfc：取挑战参数
  │    → tl：提交证明（PoW + 加密 bundle）
  │    → 回执 + 阶段元数据
  │    → reload
  │    → 200 主文档 + 新阶段标记 + 会话
  └─ 200 sensor
       → 正常页面 + 后台传感器请求
       → 会话
```

挑战脚本与业务脚本共享页面上下文：业务页里的 `KPSDK` 配置对象既可能是正常业务配置，也可能是挑战运行时的入口。判断挑战是否发生，应结合状态码、响应头阶段标记、页面体量与挑战资源请求，而不是单一字符串。

### 3.1 会话复用与逐请求校验

- **多数实例**：一次挑战或一次传感器执行后，会话可在多个文档与深页间复用；服务端主要校验会话与请求画像的一致性。
- **少数实例**：每个 URL 或每次请求都要求新的派生值；同一会话往往只能保住一次 200。客户端脚本会在同源请求上自动附加这些派生值，脱离该运行环境后静态重放无法恢复。
- **个别实例**：挑战回执被接受、会话也已写入，但主文档持续 429/循环。多种客户端栈与不同出口结果一致，指向服务端风险评分（出口信誉、画像一致性、地理等），而不是单一的 WebDriver 检测。
- **会话时效**：因实例而异；逐请求校验实例明显更短。工程语义应是“解完即用”，而不是长期囤积会话。

这三类差异说明 Kasada 不是“一次挑战、永久通行”的静态签名，而是**会话状态 + 请求级校验 + 风险评分**的组合。只还原挑战算法，无法覆盖逐请求与风险评分部分。

## 4. 检测面分类

从挑战脚本行为与对拍可归纳出以下检测面；bundle 内部权重与完整清单未还原，表里只列观察到的类别。

| 类别 | 观察 | 防御价值 |
|------|------|----------|
| 自动化/无头 | WebDriver 痕迹、无头渲染、图形适配器异常 | 识别常见自动化栈 |
| 请求画像 | TLS、UA、头序、语言/时区一致性 | 识别客户端替换与拼接头 |
| 环境指纹 | 插件、屏幕、WebGL/Canvas 等 | 提高设备区分度 |
| 行为/时序 | 页面加载、挑战完成与请求节奏 | 识别脚本化交互 |
| 出口信誉 | ASN、代理/VPN、地理与历史行为 | 风险评分 |

这些信号本身有误伤与隐私成本；权重、采集深度与保留周期需要结合业务风险评估，不能只看“检测项越多越好”。

## 5. 服务端信任边界

| 信号 | 客户端可控性 | 建议的服务端处理 |
|------|--------------|------------------|
| 挑战回执（PoW/VM 结果） | 高（客户端计算） | 校验结构、时效、一次性；不把“算得出”当作可信 |
| 会话 cookie | 高（可复制） | 绑定会话、请求画像、短 TTL；校验签发链 |
| 请求画像（TLS/UA/头序） | 中高 | 与会话、挑战、出口交叉约束 |
| 逐请求派生头 | 高（客户端运行时） | 用会话状态复算，拒绝静态拼接 |
| 环境/行为信号 | 高（可伪造） | 只作风险评分输入，不单独放行 |
| 出口/ASN 信誉 | 低（客户端不可控） | 与画像、行为组合评分；保留人工/降级通道 |

**最重要的教训：挑战完成 ≠ 可信。** 如果服务端只验挑战回执，或直接信任客户端计算的风险分，那么攻击者只要让客户端输出“低风险”即可；有效设计必须把客户端不可控或难以一致伪造的信号（会话状态、逐请求派生、出口信誉、时间窗）组合起来。

## 6. 关键实现片段（示意）

> 只保留状态推进与信任边界的结构；路径、字段名、密钥、权重、时间窗与实例值全部省略，代码不可直接运行。

```python
# 示意：挑战状态机，不含任何真实参数
def advance(state):
    if state.phase == "challenge":
        proof = client_runtime(challenge_params)   # PoW/混淆 VM，细节省略
        return submit_proof(proof)                # 服务端回执
    if state.phase == "issued":
        return load_with_session()                # 会话阶段
    return state

# 示意：服务端至少应复算的一致性；derive 细节省略
def accept(request, session):
    return (session.is_fresh()
            and request.profile == session.profile
            and request.derived == derive(session, request)
            and session.egress_ok(request))
```

| 环节 | 关键内容 | 安全含义 |
|------|----------|----------|
| 挑战执行 | PoW + 混淆 VM + 环境信号 | 提高分析成本，但不产生服务端可信状态 |
| 会话建立 | 回执 + 阶段标记 + 会话写入 | 会话必须绑定画像与时效 |
| 请求校验 | 请求级派生值与会话状态 | 静态复制会话不足以复用 |
| 风险决策 | 出口、画像、行为与历史 | 挑战通过仍可能被拒绝 |

## 7. 分析方法的合规边界

原始分析使用过网络时间线、响应头与会话写入时序、浏览器与 HTTP 客户端对拍、逐 URL 差分与出口切换实验。本文只保留方法论结论：

- 先用行为对拍区分“客户端未完成挑战”“客户端完成但服务端拒绝”“风险评分拒绝”；
- 再用阶段标记与响应头时序定位挑战状态机；
- 最后验证服务端校验的是会话、画像、派生值还是出口信誉。

**不提供**：完整 Hook 客户端、挑战 bundle 补丁、密钥、Cookie、设备号、脚本哈希/UUID、版本号与可直接运行的请求链。

## 8. 防御启示

1. **服务端复算**：会话、请求画像、时间、逐请求派生、出口至少有两项能在服务端独立验证。
2. **风险分只作辅助**：客户端评分必须与服务端可验证状态组合，不能单独决定放行。
3. **短 TTL + 逐请求 nonce**：降低会话复制与重放价值，让“一次通过”不等于“长期通行”。
4. **分阶段挑战**：传感器型与挑战型分级，按画像调整强度，兼顾正常用户摩擦与防护强度。
5. **同族隔离**：共享挑战资源要有版本隔离、灰度与回滚；单点泄露或单点绕过会影响多个实例。
6. **可观测性与误伤**：出口信誉、地理、环境信号都可能误伤合法用户，应保留降级通道与申诉机制；采集遵循最小必要。
7. **分层防护**：人机挑战只是第一层，语义 WAF、速率限制、账号与交易风控仍需独立生效。

## 9. 结论

Kasada/KPSDK 的强度不取决于混淆 VM 有多难读，而取决于服务端是否把会话、逐请求派生、请求画像与出口信誉组合成可复算的状态校验。对研究者，它是“有状态挑战 + 风险评分”的典型案例；对防御方，它提醒我们：**挑战通过只是信号，不是信任本身**。
